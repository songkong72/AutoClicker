# 관리자 명단(서버) 설정

서버(Firebase)에 개발자와 관리자 명단을 두고, 개발자가 관리자 코드를 만들어 사람마다 관리자 권한을 주고 뺏는다.
**서버 규칙을 게시하기 전에는 이 기능이 동작하지 않는다.** 관리자 비밀번호 로그인은 없어졌고, 관리자는 개발자가 만든 코드(`AD-…`)로만 들어온다.

## 1. 서버 규칙 게시

1. Firebase 콘솔 → Realtime Database → **규칙** 탭을 연다.
2. 저장소의 `database.rules.next.json` 내용을 전체 복사해 붙여 넣고 **게시**한다.
3. 이 파일이 바뀔 때마다 같은 방법으로 다시 게시한다. 게시하지 않으면 새 기능이 동작하지 않는다.
4. 게시한 뒤 아래 "게시 기록"에 날짜와 커밋 번호를 적는다.

주의: `firebase.json`은 아직 옛 파일 `database.rules.json`을 가리킨다. `firebase deploy`로 규칙을 올리면 옛 규칙으로 되돌아가므로 쓰지 않는다. 콘솔에 붙여 넣는 방법만 쓴다. (두 파일을 하나로 합치는 일은 `docs/할일.md`에 있다.)

### 게시 기록

지금 서버에 어느 규칙이 올라가 있는지 알 수 있게, 게시할 때마다 한 줄씩 적는다.

| 게시한 날 | 그때의 커밋 번호(앞 7자리) | 메모 |
|---|---|---|
| (기록 없음) | | 2026-10-08 이전 게시는 기록이 없다. 다음 게시부터 적는다. |

## 2. 개발자 등록

1. 최신 APK를 설치하고, 관리자 로그인 창(앱 위쪽 관리자 아이콘)의 **내 기기 ID** 버튼을 눌러 ID를 복사한다.
2. Firebase 콘솔 → Realtime Database → 데이터에서 루트에 `owners`를 만들고, 그 아래에 키를 복사한 ID, 값을 `true`로 적는다.
3. 앱 관리자 로그인 창에서 **칸을 비우고 확인**을 누르면 개발자로 들어온다. 관리자 메뉴 → **관리자 관리**가 열리면 성공이다.

앱을 지우고 다시 설치하면 기기 ID가 바뀐다. 그때는 1~2를 다시 하고, 옛 ID는 콘솔에서 지운다.

## 3. 관리자 추가와 삭제

- 추가: 관리자 관리 → **+ 관리자 코드 만들기** → 이름표를 적으면 코드(`AD-XXXXXXXX`)가 만들어지고 안내 문구가 복사된다. 카카오톡으로 보낸다. 받은 사람은 앱의 관리자 로그인에 그 코드를 넣는다. 코드는 한 번만, 만들 때 고른 기간(1시간 / 24시간 / 7일) 안에만 쓸 수 있다.
- 삭제: 관리자 관리 → 관리자 줄의 **삭제**. 삭제된 폰은 다음에 앱을 열 때 집결장 화면으로 돌아간다.
- 대기 중인 코드는 **코드 복사**나 **취소**를 할 수 있다.

## 관리 화면 기능

- **여러 명 코드 한꺼번에**: 이름표를 줄바꿈으로 여러 줄 적으면(최대 10명) 사람마다 코드를 만들고, 사람별 안내 문구를 한 번에 복사한다.
- **이름표 수정**: 관리자 줄의 "이름표 수정". 이름표는 관리자 항목에 저장된다.
- **마지막 접속과 앱 버전**: 관리자가 앱을 열 때마다 서버에 적는다. 최신 앱으로 업데이트한 관리자부터 보이고, 그 전에는 "접속 기록 없음 · 버전 알 수 없음"으로 나온다.
- **쓰인·만료 코드 정리**: 서버에 쌓인 코드를 지운다. 지우기 전에 관리자 이름표를 먼저 저장한다.
- **관리자 목록 보내기**: 목록을 미리 보고 카카오톡·복사·다른 앱으로 보낸다.
- **방 전체 목록(개발자 전용)**: 서버의 모든 방을 목록으로 본다. 군단 수, 집결장 배정 수, 진행 상태, 명단 인원이 보이고 방을 누르면 군단별 집결장·행군시간과 명단 이름이 나온다. 여기서 **방 삭제**를 하면 그 방과 명단이 지워진다.
- 앱 버전은 빌드할 때 git에서 자동으로 정해진다(`1.0.<커밋 개수>`). "내 기기 ID" 창에서도 볼 수 있다.

## 지금 규칙이 하는 일 (`database.rules.next.json` 기준)

아래는 이 파일을 게시했을 때의 동작이다. 실제 서버가 이 상태인지는 "게시 기록"으로 확인한다.

| 대상 | 읽기 | 쓰기 |
|---|---|---|
| 방(`rallyRooms`) | 로그인한 누구나(전체 목록 포함) | 개발자와 관리자 명단의 기기만 |
| 방 안의 행군 시간 한 칸(`teams/<번호>/marchSec`) | 위와 같음 | 로그인한 누구나(그 군단이 이미 있을 때) |
| 명단(`rallyMembers`) | 방 하나의 명단은 로그인한 누구나, 전체를 한꺼번에 읽는 것은 개발자만 | 그 방이 실제로 있을 때만. 개발자·관리자는 방이 없어도 가능 |
| 관리자 명단(`admins`) | 개발자, 그리고 자기 항목은 본인 | 개발자. 코드를 받은 사람은 자기 등록 한 번, 그 뒤로는 접속 시각·앱 버전만 |
| 관리자 코드(`adminCodes`) | 개발자만 | 개발자. 코드를 받은 사람은 "내가 썼다"는 표시 한 번만 |
| 개발자 명단(`owners`) | 본인만 | 콘솔에서만 |

- 방 문서에 `lastBy`/`lastAt`(마지막으로 바꾼 관리자 표시 이름과 시각)이 있어, 관리자 패널에 "마지막 변경: 누구 · 언제"가 보인다. 다른 관리자가 바꾸면 알림이 뜬다. 시각은 바꾼 기기의 시계 기준이다.
- 패널의 "방 선택" 목록에는 서버의 모든 방(번호, 군단 수, 집결장 배정 수, 상태)이 나오고, 목록에 없는 방으로는 이동할 수 없다.
- 규칙을 게시하지 않았거나 읽지 못하면 방 선택 창 제목에 "서버 방 목록을 불러오지 못했어요 (이유)"가 나오고, 이 기기의 입장 기록만 보인다.
- 앱도 집결장이 입장할 때 방이 있는지 먼저 확인한다. 서버 규칙은 앱을 고쳐 쓰는 경우까지 막는 안전장치다.

## 남은 한계

- **행군 시간 한 칸은 로그인한 누구나 쓸 수 있다.** 서버가 "이 사람이 그 군단의 집결장인지"를 확인하지 못하기 때문이다.
- **방 번호는 비밀이 아니다.** 로그인한 누구나 방 목록을 읽는다. 목록은 방 번호와 군단 구성만 보여 주고, 방을 고치는 일은 관리자·개발자만 한다.
- **집결장 코드(`AC-`+6자리)는 서버가 관리하지 않는다.** 앱 안에서 계산만 하므로 기한이 없고, 한 번 준 코드를 회수할 수 없다. 관리자 코드와 달리 서버 명단에도 남지 않는다.
- 이미 남아 있는 빈 번호의 명단(`rallyMembers/<번호>`)은 규칙을 게시해도 자동으로 지워지지 않으니 콘솔에서 지운다.

## 게시한 뒤 확인할 것

관리자 명단에 없는 기기는 방을 만들거나 고칠 수 없다. 관리자들이 코드로 등록했는지 먼저 확인한 뒤 게시하고, 테스트 방에서 아래를 본다.

- 관리자 폰: 새 방 만들기와 바로 입장, 시작·취소·시간 변경이 되는지
- 집결장 폰: 관리자가 만든 방에 입장·명단 등록이 되는지, 내 군단 행군 시간 변경이 되는지
- 집결장 폰: 없는 방 번호로 입장하면 "없는 방이에요"가 나오는지
- 명단에 없는 폰: 방 변경이 거절되는지
